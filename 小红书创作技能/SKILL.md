# 小红书图文创作

把一个主题变成可以直接使用的小红书笔记：可复制文案、一张封面；内容页按需再问再生成。用户只给主题时直接推进，不把流程停在大纲或生图提示词。本技能可在 **Cursor** 与 **Codex** 中使用（安装路径可能不同，行为以本文件为准）。

## 输入与默认值

必需输入只有主题。尚未给主题时，只询问主题。

可选输入：目标人群、发布目的、语气、**视觉风格（见风格表编号或名称）**、总张数、参考图片、品牌素材、真实产品资料。用户明确指定的内容优先。

收到主题后，先采用以下创作默认值并简短告知（文案可先构思，**图片必须等风格确认后再生成**）：
- 简体中文，面向对该主题感兴趣的普通读者。
- **默认只生成 1 张封面**；竖版 **3:4（1080×1440）**，适合手机阅读。落盘后必须核验真实像素，横图不得交付。
- **内容页默认不出**：封面交付后，主动问一句「要不要继续生成内容页？」；用户明确说要（如「要内容页 / 出内页 / 做完整套」）再生成。用户首条消息已要求整套/多图/内容页时可跳过再问、直接按约定张数做。
- 若用户要内容页且未指定张数：默认再出 5 张内容图（合计 6 张）；用户指定总张数或页数时按用户的来。
- 语气自然、具体、有帮助。
- 3 个标题备选，标出推荐标题；正文约 300–600 字；5–8 个相关话题标签。

### 风格确认门禁（必做，再生图）
1. 输出完整风格表（编号 1–10 + 名称 + 一句适合什么）。
2. 按主题**推荐 1–2 个编号**，各写一句理由，并标明「若你不选，默认用推荐的第一种」。
3. **停住等用户回复**：用户回复编号、风格名，或「用推荐 / 默认 / OK」后，才进入生图与落盘。
4. 用户已在首条消息写明风格（如「风格 5」「极简留白风」）→ 可跳过等待，直接采用并告知选用的编号。
5. 确认后写入视觉规范与 `prompts.md`，**先只生成封面**；用户中途说换风格 → 更新编号后重做封面，已有内容页再按需重做。

除风格外，不要为可选参数反复追问。影响内容真实性的必要资料缺失时才追问。文案可在等风格时一并交出；**不得在风格未确认时调用生图工具出图**。

## 可选风格表（封面 + 内页共用一套）

开始生图前必须选定 **一个主风格编号**，写入视觉规范与 `prompts.md`。全套页面共享该风格的背景逻辑、字体逻辑与构图气质；内页可微调信息密度，不得换成另一套完全不同的风格。

| # | 风格 | 适合什么 | 画面要点 |
|---|------|---------|---------|
| 1 | 深色渐变风 | 科技/AI/强冲击选题 | 深色渐变底，超粗大字，高对比；封面字可压在主体后 |
| 2 | 纯色扁平风 | 干货清单、清爽科普 | 纯色或近纯色底，扁平插画/图标，干净留白 |
| 3 | 产品主视觉风 | 有 UI/产品图时 | 产品或截图占 60–70%，人物或手势仅引导（无素材则用清晰界面示意，不冒充实拍） |
| 4 | 对比卡片风 | 前后对比、避坑对照 | 左右或上下两卡，近大远小或并置，差异一眼可读 |
| 5 | 极简留白风 | 金句、品牌感、少字 | 大面积留白，文字是主视觉锤，装饰极少 |
| 6 | 海报拼贴风 | 素材多、信息层次多 | 多层卡片/贴纸错落，有纵深与轻投影 |
| 7 | 人物侧置留白风 | 人设口播、经验分享 | 人物偏一侧约 25–35%，对侧大标题区 |
| 8 | 背影构图风 | 励志、旅程、启发 | 人物背对镜头，标题在视线前方留白区 |
| 9 | 局部出镜风 | 产品/步骤绝对主角 | 只露手/半脸/局部，主体给产品或步骤图 |
| 10 | 正面对视风 | 种草、信任感强 | 人物直视镜头，文字环绕安全区，不挡五官 |

**选用规则**
1. 用户已指定编号或名称 → 照用，并复述「已选风格 #N · 名称」。  
2. 用户给了参考图 → 先看图，在风格表里标出最接近的 1–2 个编号供确认（仍须等用户选，除非用户说按你推荐）。  
3. 仅有主题 → **必须先列出 1–10 全表 + 推荐**，等用户选择或确认默认后再生图。  
4. 有真实人脸/产品参考且工具支持多参考图 → 用「图1 / 图2」指代：提示词写「参考图1的五官特征」「参考图2的产品外形与配色」等，只锁关键特征，不复述图内全部细节。  
5. 无出镜需求时，风格 7/8/10 可改为「无人物」变体（保留该风格的留白与文字布局，去掉真人）。

## 文案前调研（必做，只读）

在写标题/正文前，先做一轮**小红书站内只读调研**，不登录代发、不输密码、不操作对方账号后台。可用已登录的浏览器会话打开公开搜索页；若出现登录墙/验证码，停下来说明，改用用户可贴的笔记链接，**不绕过登录**。

### 步骤
1. **账号近帖**（若用户给了自己的小红书主页/账号名）：只读最近几条，归纳已用钩子、封面类型、翻页结构、语气，避免和自己撞车。
2. **小红书同题检索（优先）**：在 `xiaohongshu.com` 用主题关键词搜索笔记（综合/最热等公开排序均可）。挑 **正好 3 条**看起来互动高的笔记，在回复和 `copy.md` 里**先列出清单**再写正文。每条必须尽量包含：
   - 笔记标题（或封面主文案）
   - 小红书笔记链接（`xiaohongshu.com` / `xhslink.com`）
   - 可见的赞、收藏、评论或浏览量（页面能读到就写数字；读不到写「数据未公开」）
   - 钩子句式、封面信息层级、正文/图文结构要点  
   **禁止**用非小红书的博客/教程页冒充「小红书高赞帖」。站外材料只能标为「补充背景」，不能替代本列表。
3. **可抄点与差异化**：在列表下方整理短表——可借鉴的结构/句式（不抄原文）；本篇差异化角度。
4. 用户可见顺序：先输出「小红书参考帖列表」→ 再请选风格 → 确认后再生图；文案可在风格确认前后交付，但参考帖列表必须在正文之前。列表写入 `copy.md` 文首「调研笔记」。

### 互动门槛与不足时的恢复路径
默认筛选：**赞 ≥ 1000 且 藏 ≥ 300**，凑满 **正好 3 条**。凑不够时按顺序处理，**不要无限卡住**：
1. **扩词**：在原主题上换/加不超过 2 个近义或场景关键词，再搜一轮（合计扩词尝试 ≤ 2 次）。
2. **降门槛**：向用户说明当前最高互动大致区间，询问是否接受更低门槛（例如赞 ≥ 500 / 藏 ≥ 100，或「按搜索结果取前 3」）；用户同意后再列清单。
3. **跳过**：仅当用户明确说「跳过调研」时跳过；跳过后在 `copy.md` 注明「用户跳过调研」，仍可写文案与选风格，但不得编造赞藏数据。

### 约束
- 只读公开页；不私信、不点赞、不收藏、不评论、不发布。
- 不编造赞藏浏览数据。
- 检索服务写作；**风格仍须用户确认后再生图**。
- 用户明确说「跳过调研」时可跳过（见上恢复路径第 3 步）。

## 文案与逐页策划

1. 基于调研的差异化角度，明确读者看完能解决的一个问题，选择具体切入点，避免把宽泛主题堆成知识清单。
2. 标题给出明确对象与价值，不编造效果保证、销量、数据或亲身体验。推荐标题同时用于封面，但允许为版面缩短。
3. 正文用短段落讲清问题、方法与适用条件，补充图片没有展开的细节；结尾可有一句自然的交流邀请。不要机械堆叠感叹号、表情或互动口号。
4. 根据主题设计连续的翻页逻辑。例如：封面 → 常见问题 → 核心方法 → 实例 → 行动清单 → 总结。不同主题可以改变结构，不强套六步模板。
5. 为每张图确定：页码、目的、准确上屏文字、主体画面、版式。每页一个重点；封面标题通常 8–16 字，内容页标题通常 6–14 字，正文通常 30–80 字，必要时拆页而不是缩成小字。
6. 最新资讯、价格、产品参数、专业或高风险事实按需要查证，并在文案文件末尾记录来源。纯创意题材不必强行搜索。无法确认的事实不要包装成确定结论。

逐页文案要完整可用，不能让生图工具自行编写大段中文。用户已经提供文案时，尊重其措辞与重点。

## 统一视觉与实际生图

使用**当前宿主环境里可用的图片生成工具**，不要写死某一产品名：
- **Codex**：优先用本机已安装的 `imagegen` 技能（首次使用先读其说明）。
- **Cursor**：优先用内置的 `GenerateImage`（或当前会话实际提供的等价生图工具）。
- 其他环境：用该环境文档标明的内置生图能力；不要求用户自备 API Key 才能用内置工具。

每次请求必须明确要求竖版肖像比例 **3:4**（目标 **1080×1440**）。工具返回后**以落盘文件真实像素为准**核验，不能把参数里的比例当成已验证结果。

开始生图前固定一份简短视觉规范（必须含风格编号与名称）：
- 画幅 3:4；**主风格 #N · 名称**；背景色、主色、强调色（对照上表色板；深色渐变风偏深底浅字，极简留白/纯色扁平偏浅底深字）。
- 统一中文标题层级、正文大小、对齐方式与留白；重要内容留在四周约 6% 的安全区域内（人物出镜时可提到约 10%）。
- 统一插画或摄影语言、装饰元素、页码位置；封面更醒目，内容页保持同系列辨识度。
- 每张图有清晰阅读顺序和充足对比度。页面变化服务于内容，不把每页做成互不相干的海报。
- **禁止**：把同一套颜色字体套到所有风格上；廉价发光/全息/粒子堆砌（除非用户明确要求）。

**默认流程：只生成封面并检查像素（3:4）后交付。** 交付封面时问用户是否要内容页；未获同意前不要生成内容页。

用户确认要内容页后：将已确认封面作为视觉风格参考，再逐张生成内容页。参考封面仅用于统一风格，不要求复制封面内容。每张图独立生成、独立交付，不要把多张图合成一张大拼图充数。

每次提示词写清：
1. 当前页的作用和构图（符合选定风格要点）。
2. 全套统一视觉规范、风格编号及竖版比例。
3. 需要逐字呈现的中文文字，使用引号明确界定。
4. 当前页视觉主体、标题与正文位置；姿势/空间关系写具体（手在哪、谁在前谁在后）。
5. 不添加额外文字、水印、虚构标志或无关元素。

用户给了人物、产品或品牌参考时，先查看素材，再在工具支持的范围内用作参考，保持关键特征一致。无现成素材时可生成匹配主题的插画或场景，不冒充真实产品实拍。

## 检查与修改

查看每张实际生成图片，重点检查：中文错字和乱码、文字被裁切、信息与文案不一致、主体遮挡文字、页码遗漏，以及全套是否仍是选定风格。以手机阅读尺寸判断，信息过密时优先删减文字或拆页。

发现问题时针对该页修正并重新查看，通常最多两轮；仍存在的问题如实标明，不宣称已经完美。用户只改某页时保留其余已认可图片。用户要求换风格时，更新视觉规范后重做封面，再按需重做内容页。

目标为竖版 **3:4**（推荐 **1080×1440**，宽/高 ≈ **0.75**）。每张图落盘后必须用工具读真实像素（如 `identify`、PIL `Image.size`，或本技能 `scripts/ensure_3x4.py`），在回复里写出「宽×高」；**禁止**把提示词里的比例或工具参数当成已验证结果。

若实际宽高比不是 3:4（例如误出 16:9 / 1280×720）：**不得直接交付横图或非 3:4 图**。处理顺序：
1. 重试生图并显式传入竖版 3:4；
2. 若工具仍输出错误比例，运行本技能目录下的  
   `python3 scripts/ensure_3x4.py <输入图> [-o 输出.png] [--bg R,G,B]`  
   （默认在输入旁写出 `*-3x4.png`；仅加 `--force` 才覆盖原文件）。脚本会垫色或居中裁切到 3:4 再缩放到 **1080×1440**，并打印最终宽×高；退出码非 0 表示仍不合格。
3. 再核验一次像素，确认 1080×1440（或严格 3:4）后才交付。

如果图片工具不可用，先交付文案、逐页方案、**选定风格**和生图提示词，明确说明实际图片尚未生成。不要用占位图冒充完成，也不要未经用户选择切换到需付费凭据的外部服务。

## 文件与交付

在当前工作目录下建立独立的 `output/xiaohongshu/<主题简称>/` 文件夹；同名已存在时加序号，避免覆盖。保存实际可取得的文件：
- `copy.md`：标题备选、推荐标题、正文、标签；有事实引用时附来源。
- `01-cover.png`：封面（默认必有）。
- `02-content.png` 起：仅在用户要内容页时再生成并保存。
- `prompts.md`：视觉规范（含风格编号）、封面（及已生成内容页）文案与实际提示词，便于后续修改。

以上图片文件名以实际格式为准，不能仅改后缀冒充 PNG。使用工具返回的真实文件路径保存或复制，不编造路径，也不声称未落盘文件已经保存。能提供本地文件时可附整套压缩包。

最终给出推荐标题、可复制的正文与标签，展示封面，并提供文件入口；若已生成内容页再一并展示。图片已在工具输出中清晰展示时不用重复全部图片。注明已交付张数（默认 1 张封面）与**使用的风格 #N**；提示词是辅助材料，不代替图片成果。

本技能负责内容制作。只有用户明确要求发布时，才另行处理登录、账号选择和发布动作。

## 调用示例

**默认（只出封面）**
- “用 $xiaohongshu-content，主题是新手咖啡入门，面向上班族。”
- “用 $xiaohongshu-content，主题是 AI Agent 入门，推荐风格后按你选的做；我有一张正脸和一张 App 截图。”
- “用 $xiaohongshu-content，主题是租房卧室改造，风格用 5 极简留白风。”（默认只出封面；若再说「再出内容页」才继续）

**明确要内容页 / 整套时（可跳过「要不要内容页」再问）**
- “用 $xiaohongshu-content，主题是租房卧室改造，做一套小红书图文（封面+内容页）。”
- “用 $xiaohongshu-content，主题是装修避坑，风格 2，封面和内容页都要，共 6 张。”
